# 公司/组织设计能约束 agent 吗？什么可控，什么不可控

> 对 org & identity v1（PR7）之后代码的审阅结论（读代码 + 跑测试 + 在临时目录做实验）。行号指 `postoffice`（以审阅时的提交为准，改动后会漂移）。

## 结论

**公司、项目、成员、角色这一层不约束 agent 的行为。** 它做两件事：导入时校验配置（坏引用、越界成员、v1 配置里出现 `organization` 都会被拒，旧文件保持不变）；以及算出一份只读的「身份」（谁是成员、谁现任什么角色、规章文件和进度文件的路径），显示在 CONTACT.md、面板、`identity` 命令和会话开头的一行提示里。`send`、`broadcast`、`ack`、`retract`、别名解析（选谁收信）、唤醒路径都不读成员、角色或公司规章。唯一用到角色的地方是别名切换/交接通知：按角色范围派生出规章与进度文件的路径，写进通知文字（`alias_handoff_path`，约 1586 行），仍然只是文字指针。

被代码**真正强制**的是投递管道：别名取第一个在线候选、离线开关、撤回/修改与投递的竞争、唤醒限速、正文永不注入唤醒文本。但这些也**没有身份认证**：所有命令都信任调用者传的信箱名，所有 agent 又是同一个系统用户。所以它约束的是「按 skill 办事的诚实 agent」，约束不了「跑偏或恶意的 agent」。

一句话：**这是协作系统，不是权限系统。** 组织设计的价值是让人看得清、让 agent 知道该找谁，而不是拦住谁。

## 只是建议的

| 项目 | 为什么不是约束 |
| --- | --- |
| 公司 `rules_file`、项目 `status_file` | 只打印路径；代码只读它来显示「存在/缺失」。`config show` 明说「邮局不读这个文件」 |
| 角色名、现任 vs 候选 | 仅显示。候选角色照样能 `send`/`ack`/`clear`；同一个箱可以同时是 OWNER 和 REVIEW |
| 成员名单 | 没有任何命令查它；非成员可以给成员或 `@po.owner` 发信（已验证） |
| `panel.organization` 树 | 纯展示，与 `organization.companies`/角色没有任何关联，也互不校验（两个同名字段，含义不同） |
| 票据里的 OWNER_ROLE / REVIEW_ROLE | 没有代码解析 |
| 「先读规章、变了重读」 | 没有机制跟踪 |
| skill 里的规矩（信不是授权、找直属上级、别擅自下线别人、别 `mv` 邮件文件） | skill 自己说是「使用规定，不是权限系统」，还告诉 agent 跑不了命令时可以直接写 inbox 文件 |
| 唤醒文本的尾巴 | 是请求；没人验证 agent 读没读、回没回、归没归 |
| 广播截止时间 | 只决定汇总信何时出现；没有升级、没有后果 |

## 你能控制什么（对照表）

| 手段 | 能拦住 | 拦不住 |
| --- | --- | --- |
| 关掉一个会话（`offline`、面板钥匙） | 该信箱的新唤醒；别名绕开它 | 已经在跑的 agent：它仍能发信、广播、回执、读写文件，还能给自己 `online`。离线的会话照常能发信 |
| 关一个分组 | 同上，对全体成员 | 同上 |
| 归档（`clear`、`archive-current`、面板） | 未投递的积压 | 已发出的唤醒；文件仍可读；任何调用者可指定任何信箱，`archive-current --box X` 没有身份检查 |
| 撤回/修改 | 通道还没接受的信，并发安全 | 已送达/在途/通道未知的信；而且可伪造：「是否自己的信」只比对头里的发件人字符串（已验证可冒名撤回） |
| 回执 | 什么也拦不住，只是记账 | 任何人可冒名回执；回执不证明干了活 |
| 限速 | 每信箱每 10 分钟超过 6 次唤醒 | 信的数量：没有每发信人配额、没有收件箱上限；OpenCode 计数在内存里，重启清零 |
| 钩子限制（7 天超时、20 分钟提醒） | 约束的是监视者，并提醒人 | 一个从不读信的 agent：只有桌面弹窗；它仍算「在线」，路由不会改道 |
| 广播截止 | 无 | 缺的回执只在汇总信里体现 |
| 直接写文件 | 无：手写进 inbox 的 `.md` 会照常投递，来源可随便写 | 同样没保护：`routes.json`、`config.json`、`acks.jsonl`、`.seen`、账本 |
| 面板 HTTP | 跨站浏览器 POST（403，已验证） | 本机 curl 不带 Origin 就能调；`/api/send` 接受任何已登记的 `from`；`/api/status`、`/api/clear` 不需要发件人 |

## 缺口与风险（按重要性）

1. **发件人没有认证。** `send/broadcast/ack/edit/retract` 都把发件人当自由参数，`cmd_send` 甚至不检查它是否登记（2209-2224）。任何 agent 都能冒名 `boss` 发信、冒名回执、撤回别人的信。便宜的修法：校验发件人是已登记信箱且符合 NAME_RE；OpenCode 加一个绑定 `ctx.sessionID` 的 `postoffice_send` 工具。真认证要每个 agent 一个系统用户，不便宜。在那之前应当对外说明：这是协作系统。
2. **组织不产生发信策略。** 想让公司/项目真正起作用，可加可选 `policy: warn|deny`：发信人与收信人必须同项目或同公司（约 30 行），但在第 1 条修好之前没有意义。
3. **头部与路径注入（已验证）。** 主题里的换行可注入 `广播：B…` 之类的头，把普通信变成「派生通知」（不可撤回、不催）；发件人写成 `../../../escape/x` 在 `inbox/` 外写出了文件，还留下垃圾目录（545, 550）。修法：主题/需要/发件人拒绝控制字符，发件人必须符合 NAME_RE（便宜）。
4. **主题和需要的文字会不经过滤进入模型**，且被包装成邮局的话（451-460），是任何发信人都能用的提示词注入通道；「不是授权」只是 skill 里的一句话。便宜的缓解：只留一行并限长。
5. **删掉一个信箱会让所有别名和分组失效**（1012, 2034，已验证）。修法：`remove` 时若被配置引用就拒绝或警告（便宜）。
6. **「在线」是手动旗标。** 崩溃或卡死但仍标在线的会话会一直收别名流量；只有人被提醒（1402-1406）。修法：在 `send`/`config show` 里提示活动是否陈旧（便宜）；自动改道是设计变更（中等）。
7. **没人读的信没有后果**，只有弹窗（3757）。可选地改道或升级到别名的 `notify` 名单（中等）。
8. **CONTACT.md 会过期**：`config import` 不重写名片，新的成员/规章行要等下一次 `add/online/offline`（2153-2175，已验证）。导入后刷新全部名片，或去掉这些行（便宜）。
9. **相对路径的 `rules_file` 从不解析**，而文档示例用的正是 `"rules.md"`（ORG_IDENTITY_V1.md:36）；只有 `status_file` 会按项目根解析（1696）。校验时要求绝对路径（便宜）。
10. **Claude 钩子没有批量上限**（3634-3656），postman 和插件有。切片到 `MAX_FORMAL_BATCH`（便宜）。
11. **面板 `/api/send` 不强制 `from = panel.operator`**（4591-4596），而 edit/retract 强制了（便宜）。
12. **同一个箱同时现任 OWNER 和 REVIEW 没有警告**（示例文档自己称之为自审）。在 `identity` 和 `config show` 里加警告（便宜）。

## 文档/测试/代码互相矛盾的地方

- 信头写「邮局只确认来源信箱」（550；README 124 行、README.zh-CN 121 行）：邮局什么也没确认，只记录传进来的字符串。
- `tests/hook_rate_test.py:418` 过期：期待唤醒文本里有「来源：boss（邮局只确认…）」，而代码刻意输出中性的 `来源：boss`（451-460），`provenance_test` 也强制这一点。代码对，测试错。
- README 27 行说「超过 20 封分轮发出」，Claude 钩子路径没有这个上限。
- `docs/ORG_IDENTITY_V1.md:73` 说 `active` 复用发信方的 `alias_target`；实际 `resolve_alias` 有自己的循环（1421-1428），只有配置合法时两者一致。
- `docs/DELIVERY_org_identity_v1.md` 写「未 push、未合并」，但 `git log` 已有 `c42737b merge … (PR7)`；README 282 / README.zh-CN 269 行说 22 个测试，文件里是 23 个。
- `docs/ORG_IDENTITY_V1.md`、`ORG_CONTRACT_EXAMPLE.md` 没提：`panel.organization`（展示树）和顶层 `organization`（公司与项目）同名但无关，也互不校验。
