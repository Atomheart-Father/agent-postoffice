# v1.7 实施规格：分组开关、逻辑地址与切换广播

状态：已按用户需求及管理员转述授权进入实施；不是发布或部署授权。

Codex 负责规格、实施验收；OpenCode 邮局开发负责实现；管理员追加终审。

## 1. 唯一配置与名字

新增 `POSTOFFICE_HOME/config.json`，`version: 1`。`routes.json` 保持物理信箱、身份和在线状态的唯一来源，不迁移结构，不增加组状态。

用户命令与面板使用 `@codex`、`@project.manager`。JSON 对象键保留需求示例的无前缀形式 `codex`、`project.manager`；`@` 是调用前缀，引用物理信箱不加 `@`。组和逻辑地址共享名字空间，撞名直接拒绝；名字只接受英文字母、数字、下划线、横线和点，不接受路径、空白、通配符。组成员与候选、通知收件人只能是已登记的具体信箱，禁止嵌套。列表保持输入顺序，重复成员/候选/通知对象拒绝，避免重复状态操作和广播。

```json
{
  "version": 1,
  "groups": {"codex": ["manager_b"], "claude": ["manager_a"]},
  "aliases": {
    "project.manager": {
      "candidates": ["manager_a", "manager_b"],
      "notify": ["developer"],
      "handoff": "/path/to/project/handoff.md"
    }
  }
}
```

兼容原始需求的 alias 数组写法：等价于 candidates 数组，notify 为空，无 handoff。对象写法 candidates 必需且非空；notify 可省略，handoff 可省略且必须为字符串。handoff 只作为路径元数据传递，邮局不读取文件，不执行路径内容。不将本机实际角色配置、个人路径或会话记录写进公共仓库。

`postoffice config import FILE`：验证 JSON/版本/结构/名字/引用后才修改；失败非零且旧配置字节不变，不改 routes、不发信。成功前把旧文件备份到 logs，临时文件原子替换，整文件替换而非 merge。拒绝 JSON 重复键，避免撞名被解析器悄悄覆盖。`config show` 显示配置；尚未配置时给清楚说明，不创建默认配置或改状态。

配置每次使用时重新读取。缺配置表示功能未启用，原有物理信箱功能照常。坏配置不使邮递员退出；新增功能停用并记清楚诊断，不凭旧缓存猜地址。已导入后某引用信箱被删除，相关操作报错，不能部分展开或静默跳过。

## 2. 分组操作与面板

`offline @GROUP` / `online @GROUP` / `clear @GROUP` 只接受 group；`send @ALIAS` 只接受 alias，不混用。单信箱命令行为保持。

组操作先校验全部成员，再调用现有单信箱行为；不在输入/引用无效时改一半。online_since 只在成员真正离线转在线时更新，重复 online 不刷新。clear 沿用存档而非删除，逐成员列出数量及去向。组允许为空，输出 0 个成员，无隐含 all。

面板新增小型 Groups 区：外部名字、在线数/总数、全开/全关按钮，保留单信箱开关。按钮沿用同一状态接口/本机来源检查；无新控制页、不改变其他权限。

## 3. send 时立即选择当前经理

alias 按 candidates 顺序，选择当前第一个 online 物理信箱，在执行 send 时解析一次。打印逻辑地址到物理信箱的解析结果；信头可记 `逻辑地址：@NAME` 作为审计元数据，回执仍回原发件人。

所有候选离线：非零，列候选状态；不读 stdin 等待正文，不投到任何候选 inbox，不生成待补送的 alias 信。物理信箱 send 的离线存信行为保持。

60 秒稳定确认仅约束切换通知，不延迟新信路由：候选变化后新 send 立即按当前在线状态选人。旧信、旧通知、ACK 的原发件人位置不搬家、不重新路由。广播站通知和交接只报告收件路由变化，不自行授予其他项目经理权限、启动 Ticket 或替人做任务。

## 4. 邮递员切换广播站

纯 JSON 小状态文件记录每个 alias 的已确认目标、待确认目标和开始时间；它是通知去重状态，不是第二套在线状态。每轮从 config/routes 计算实际目标。目标连续稳定 60 秒才确认一次；A→B→A 在时限内取消待切换、不广播。测试可用环境变量缩短时间，生产默认 60 秒。

首次发现配置中正常有目标的 alias：登记初始基线，不冒充经理已经发生切换，不发启动广播。首次发现无在线候选：稳定期后发一次无人接任通知和系统通知。已确认无候选→有人、备用→主事恢复、配置调整导致目标变化，同样按稳定期确认。重启保留基线/待确认时间和已发通知的去重记录，不重复通知。移除 alias 清理其待确认状态，不额外广播；重新添加按新启用处理。

确认切换时：

1. 对 notify 的具体信箱发一次现有 broadcast，需 ACK；各收件箱离线时存信，沿用现有投递与汇总。空 notify 不制造空广播。
2. 有接手目标时向它发一封交接提醒，说明前后对象、原因和 handoff 路径（可为空）；不读取交接文件、不触发自动工作。交接信标 `需要：仅告知`。
3. 写 `logs/alias_switch.log`：事件编号、时间、alias、前后目标、原因、通知对象、交接目标。原因基于实际变化：旧目标下线/高优先级候选恢复/配置调整/候选全离线，不一律编造“下线”。面板显示当前实际解析对象及最近确认切换记录；两者尚处稳定期不同要明确展示。
4. 无候选时只向 notify 和人通知；没有交接收件人，不投到任意候选 inbox。事件文案不作为人的新授权。

使用现有写信/广播能力，但系统来源应可由现有 `postoffice` 系统信源表示，不要求新增在线系统模型会话。每个切换事件需要可恢复的确定事件编号；广播与交接分步骤去重：只成功发广播、交接失败后恢复时不能重发广播；反之亦然。重启/中途失败以原事件重试，不生成新事件刷信。若已有步骤被用户归档/删除，不因此重发。无需数据库、工作流框架或新传输通道。

## 5. 两项兼容修复

### 广播信按物理信编号 ACK

`ack BOX LETTER_ID` 找到本箱的信时，若其头部有 `广播：BID`，验证真实广播记录及本箱成员身份，再按 BID 记广播 ACK。直接 ACK BID 与 ACK LETTER_ID 都归一到同一 BID，先归一再查重复：混用也只记录一条、只计一人。可在 done 找已处理信以支持幂等。正文伪造广播标记不算，不能跨信箱记账；不信任标题，不把损坏/不存在广播静默退成普通 ACK。

### 按原 ID 归档回执时先显示数量

保留 `archive-receipt BOX ID` 单 ID 接口：先精确扫描头部、显示匹配 N 条，再检查全体冲突并移动；无匹配显示 0 并成功，冲突仍整批不动/非零。数量包含匹配通知而非账本条数，不查看正文。不开默认 all、不增加交互确认，不改 receipt 只读语义；修正仍可一编号对应多封通知的说明。
