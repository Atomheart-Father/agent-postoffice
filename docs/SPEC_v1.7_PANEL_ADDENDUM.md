# v1.7 面板补充：投递状态与中英文

用户追加授权：纠正面板“积压”误导，并补齐中英文界面；并入当前 v1.7 批次，不另开发布。

## 已证问题

面板把所有 inbox 文件计为“积压”。Manager 的一条 ACK 通知已在 `.seen` 留下投递记录，仍被显示为积压 1 封。清空按钮声称只存档“还没送出的信”，实际沿用 clear_backlog 存档全部 inbox，包含已提醒的信。面板全部文案目前仅中文。

## 1. 状态展示

每箱显示“待投递 N / 已提醒待归档 M”，列表标明每封状态。已提醒只表示提醒被通道接受，不保证模型已读、工作完成。来源按实际通道：Claude `.seen`、OpenCode 台账中的 DELIVERED、Codex `.woken.json` 的接受记录；不要把 `.delivered.json` 的失败/超时兜底标记当成成功提醒，也不要把 FAILED_FINAL 算成 DELIVERED。

发送失败已停止自动重试的信，若可从现有台账判定，单列“投递失败，需人工处理”，不混称等待自动补送；不新增投递状态库。没有成功记录的仍显示待投递，不猜模型阅读状态。数量和文件列表由后端同一快照得出，避免前端与后端不同口径。

组面板新增能力也使用同样口径。原 clear 行为不改：按钮改为“归档信箱内全部通知/信件”，确认明确同时包含待投递与已提醒未归档的信、保留文件、待投递信归档后不再补送。没有 inbox 信件时不显示操作按钮。不得自动归档、自动查回执正文或删除信件，也不改清空组行为。

## 2. 中英文

面板新增明显的 中文 / English 切换。首次按浏览器语言选中文或英文，其他语言回落英文；手动选择存 localStorage，刷新保持；存储不可用也能切换。只切换显示，不改变信箱状态、不调用任何写入接口、不触发唤醒。

覆盖标题、说明、开关状态与辅助标签、数量、按钮、确认框、空列表、错误提示、广播状态、Groups 区、逻辑地址当前目标/稳定期与切换历史状态。不翻译用户信件标题、信箱名、回执正文、交接路径或原始日志；原始日志明确作为原文显示。日期/数量按当前语言显示即可，不新增翻译依赖或模型调用。

集中维护小型 zh/en 文案表，不引入框架或构建系统。保持现有页面布局、来源检查与转义。

## 3. 验收

临时信箱/API：已提醒 ACK 留在 inbox → 已提醒待归档 1、待投递 0；未投正式信 → 待投递 1；FAILED_FINAL 或超时人工兜底不能假装已提醒。列表与数量一致，移入 done 后消失；清空原行为仍可恢复文件，确认文字覆盖全部 inbox。

界面：中英切换覆盖原面板及新 Groups/alias 区；刷新保留；切换不调用状态/清空写入接口；用户原始内容保持原文且转义；确认框、错误和空状态也随语言变化。用有界公共页面/API测试核验，不只断言文案表键存在。

沿用 v1.7 文件范围及隔离测试约束；完成时报告英文覆盖和真实页面核验方法。此次仅授权 lab 实施，不部署、不重启、不 push。公共文档同步新的统计定义与面板语言选择。
