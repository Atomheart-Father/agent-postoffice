# 开发说明：回执记账（ack）与广播（broadcast）

## 现行规则（v1.7）

本节是当前唯一权威规则。下面的“历史档案”是已过时的早期开发记录，仅供追溯，不要按它执行。

- 要等对方答复才能继续的信（需要：回复 / 审核）→ 照旧用 `send` 回一封正式信（会叫醒对方）。
- “仅告知”的信、收尾的 copy that → 用 `ack` 记账，把原信挪进 `done/`，并通过现有投递通道在空闲时通知发信方。
- 回执提醒**三行以内**：来源 + 原事由（截短）、一条查询命令、“默认不答复”；广播汇总只给人数/截止/未回者加一条查询命令。都不附回执正文、note 或各人一句话；收到回执默认不答复、不再 ack。同一信箱一次唤醒里正式信在前；多条回执合并成一条“另有 N 条回执”清单（各带来源、原事由与查询命令）放最后，单条时才用三行形态。
- 回执正文的唯一来源是 `<HOME>/acks.jsonl`。模型用只读命令按精确 ID 查询，看完用 `archive-receipt` 归档：

  ```
  postoffice receipt <你的信箱> <回执ID>            # 普通信=原信件编号；广播=广播编号
  postoffice archive-receipt <你的信箱> <回执ID>    # 只归档本箱对应回执通知，幂等
  ```

  未登记信箱、未知 ID、别人的回执：非零退出、简明报错、不泄露其他信箱内容。`receipt` 不发信、不 ack、不移动信、不改在线状态、不叫醒任何会话；`archive-receipt` **先显示匹配到几封**（一个 ID 可对应多封通知；0 封也算成功），再核全体冲突：任一 `done/` 已有同名文件就不移动任何一封、非零退出、源与目标都保留，重复运行无影响。它只按通知头的 `回执：<ID>` 精确匹配本箱 `inbox/`（只看信头块，正文里伪造的标记不算），不读正文、不改账本、不发信、不叫醒。这是调用者显式指定 ID 的手动操作，从不自动归档。
- 广播按**物理信编号**回执：信头带 `广播：<BID>` 时，`ack` 先归一到 BID 再查重复，所以直接 ACK BID 和 ACK 信件编号只记一条、只计一人；标着广播却没有记录、或不是发给本箱的，一律报错不记账，不静默退成普通信回执。广播标记只看信头块，正文伪造不算，也不能跨信箱记账。已在 `done/` 的信同样能找到，重复 ack 幂等。
- 回执正文按通知头的 `回执：<ID>` 标记识别，不看标题/正文：正式 `send` 即使事由以“回执：”开头也仍是普通信，不会被当成回执通知。
- 通知文件只存索引/元数据（来源、原事由、`回执：<ID>`）。旧版本把正文写在通知文件里的，也只按元数据提醒，不注入。
- 广播：`broadcast` 给每个收件人各投一封带编号的信；收件人用 `ack <自己的信箱> <广播编号>` 回执；全员回齐或过截止时间后，给发信方投**一封**汇总。广播的 `receipt` 查询还会给出汇总状态与未回执的人。由系统发出的广播（发信方不是信箱、汇总无处可投）安静跳过汇总并只处理一次，不会反复重试。
- `ack --wake`：普通信本来就会发回执通知，`--wake` 只把标题改成 `copy that`；广播默认不逐人发通知，加 `--wake` 才另投一封 `copy that` 通知。
- 提醒只服务真阻塞：30 分钟未处理提醒按优先级分类——①回执通知/广播汇总不提醒；②`需要：` 恰为 `回复`/`审核` 提醒、恰为 `仅告知` 不提醒；③自由文本只含肯定词（回复/审核/处理/修改/决定/确认）提醒、只含否定词（仅告知/无需/不用回/默认不答复/无需操作）不提醒；④正负混合或识别不了照旧提醒（不宣称零误报）；`send` 写入前去掉重复的“需要：”前缀。20 分钟未送达计时起点取 `max(信件写入时间, 该信箱最近一次转为在线的时间)`；`online_since` 只在真正 offline→online 时更新、重复点在线不刷新，升级时已在线又无基线的信箱以邮递员首次新版运行时间为基线，离线时长不计。
- 提醒里出现的查询命令都做 shell 引用（信箱、ID 可能含空格与 `（）;'` 等字符）。
- 面板的逐信统计（v1.7）：每封信按各通道**真实台账**判状态——待投递（还没发）、已提醒待归档（通道已接受提醒、信还在 `inbox/`）、投递失败（该通道已放弃）。已提醒取 Claude 的 `.seen`、OpenCode 台账的 `DELIVERED` 行、邮递员 `.woken.json` 的接受记录；**不读 `.delivered.json`**（那里混着 20 分钟兜底记号，不算提醒），`FAILED_FINAL` 算投递失败而不是已送达。计数与列表取自同一份快照，不新增状态库，也不自动归档、不查回执正文、不删信；`clear` 行为不变，按钮文案改为“归档信箱内全部通知/信件”，明确同时包含待投递与已提醒未归档，保留文件、待投递信归档后不再补送，信箱为空时不显示该按钮。
- 面板的中英切换（v1.7）：首次按浏览器语言（`zh*` 中文，其余英文），页面上有显式的中文 / English 按钮，手动选择存 `localStorage`、刷新保持，存储不可用也能切。切换**只重画**：不改状态、不调用写入接口、不触发唤醒。覆盖标题、说明、开关状态与 aria、数量、按钮、确认框、空列表、错误提示、广播状态、Groups 区、逻辑地址目标/稳定期/切换历史；信箱名、信件事由、回执正文、交接路径、原始日志一律按原文显示并转义。
- 分组与逻辑地址（v1.7，细则见 `docs/SPEC_v1.7.md`）：`offline/online/clear @GROUP` 只接受分组，先校验全部成员再套用现有单信箱行为、引用了已删除的信箱就整体拒绝；`send @ALIAS` 在发信那一刻解析第一个在线候选、全部离线就非零退出且不投递；候选稳定 60 秒后确认一次切换并广播 + 交接 + 写 `logs/alias_switch.log`，广播与交接分步骤去重、失败只补未完成的那一步。这些能力都在 `config.json` 存在时才有，坏配置只停用新功能、不影响物理信箱，也不动 OpenCode 插件。

## 历史档案：早期 ack / broadcast 开发记录（已过时）

> 以下为早期设计、实现与测试记录，规则已被上面的 v1.5 覆盖，保留仅为追溯。其中的“不叫醒”等叙述不再适用。

### 要解决的问题

1. 每封信都要回执（copy that），每封回执都会叫醒对方：“仅告知”的信和收尾的 copy that 也叫醒一次，打断对方上下文、浪费调用。
2. 通知所有人只能逐个发信，每人再各回一封 copy that，发信方被一封封回执反复叫醒，信箱很乱。

### 当时的规则

- 对方要等你答复才能继续（需要：回复 / 审核）→ 照旧用 `send` 回一封正式信。
- “仅告知”的信、收尾的 copy that → 用 `ack` 记账，当时不叫醒对方（现行规则已改为空闲时发元数据通知）。
- 广播 → 每人用 `ack` 回执；全员回齐（或到截止时间）才给发信方投**一封**汇总信。

### 当时的接口

- **信件编号** = 文件名去掉 `.md`；`send` 成功后打印。三行信头（来源 / 事由 / 需要）不变；广播信在第 4 行加 `广播：<广播编号>`。
- **`postoffice ack <我的信箱> <信件编号|广播编号> ["一句话"] [--wake]`**：在 `<HOME>/acks.jsonl` 追加 `{time, by, id, kind, note, to}`，`to` 取信头“来源：”的第一个词（广播取广播记录的发信方）；把原信挪进 `done/`；同一人对同一编号重复 ack 幂等；编号不存在或不是发给我的则报错、不写账。
- **`postoffice broadcast <信箱,..|all> <发信信箱> "<事由>" "<需要>" [--deadline 30m] [--file F]`**：广播编号 `B<YYYYMMDD-HHMMSS>_<发信方>`，记录到 `<HOME>/broadcasts/<编号>.json`；给每人各投一封带编号的信（受各自在线/离线管）；默认截止 30 分钟（可用 `POSTOFFICE_BROADCAST_DEADLINE` 秒级覆盖）。
- **邮递员汇总**：每轮检查 `broadcasts/*.json`，全员 ack 或过截止且未汇总 → 给发信方投一封汇总并标记 `summarized`；只发一次。
- **面板**：`/api/state` 增加 `broadcasts`（最近 10 个）和每信箱最近回执；页面加“广播”区块与“最近回执”。

### 当时的测试

1. ack 普通信：写账、信挪到 done。
2. `ack --wake`：原发信方 inbox 多一封 `copy that：…`。
3. 重复 ack 幂等；ack 不存在的编号报错、不写账。
4. broadcast 给 3 个信箱（其中 1 个离线）：各自 inbox 一封，第 4 行有广播编号。
5. 未到截止、未全员 → 不汇总；全员 ack → 恰好一封汇总；邮递员重启不重复。
6. 过截止仍有人没回：汇总列出未回执的人（用环境变量把截止调成秒级）。
7. 原有收发信等用例继续通过。

这些用例后来演进为 `tests/smoke.sh`（现为 46 项）与 `tests/receipt_test.py`。
